# codingStandards

Purpose: concise rules to guide edits and responses; include only user-requested guidelines.

1. Change approval
1a. Never make changes I haven't explicitly requested and then approved.
1b. If you propose changes, present them as a todo list and wait for my approval before editing.

2. Scope coverage
2a. Always address every item I instruct you to affect.
2b. If an instruction lists multiple items, confirm you will cover each one in the todo list.

3. Task planning & submission
3a. For any non-trivial action, create a concise todo list and submit it for my approval.
3b. Todo list should include:
3b1. A short numbered list of concrete steps (1, 2, 3...).
3b2. Files/locations to be changed (use `path/to/file` syntax).
3b3. One-line success criteria for verification.

4. Formatting of lists/indents
4a. Use alphanumeric indenting, not bullet glyphs.
4b. Format follows: top-level numbers (1, 2, 3), first-level subitems use letters appended to the parent (e.g., 5a, 5b), next-level subitems use numbers appended after the letter (e.g., 5a1, 5a2), etc.
4c. Example:
4c1. 1. Task
4c2. 1a. Subtask
4c3. 1a1. Sub-subtask

End.
